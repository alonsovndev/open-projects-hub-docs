# 1. 📌 Información General

## Nombre del Producto
Open Freelancer Project Hub

## Tipo de Producto
Plataforma Web Open Source para gestión de proyectos freelance asistida con IA.

## Naturaleza
Proyecto Open Source.

Objetivo:
- Servir como proyecto académico.
- Ser una herramienta real utilizable.
- Permitir contribuciones futuras de la comunidad.

---

# 2. 🎯 Objetivo del Proyecto

Desarrollar en un plazo de **1 a 1.5 meses** un MVP funcional que permita:

- Gestión de proyectos freelance
- Gestión básica de clientes
- Refinamiento de requerimientos con IA
- Generación automática de user stories
- Gestión de roles y permisos
- Aplicación de buenas prácticas de ingeniería

---

# 3. 🧠 Problema a Resolver

Freelancers necesitan:

- Mejor estructura de requerimientos
- Automatización en documentación
- Organización clara de proyectos
- Control de acceso en proyectos colaborativos
- Seguridad robusta

---

# 4. 👥 Usuarios y Roles

## 4.1 Roles del Sistema

### 1. Administrador
- Gestión completa del sistema
- Gestión de usuarios
- Gestión de proyectos
- Asignación de roles

### 2. Superusuario
- Gestión de sus propios proyectos
- Gestión de clientes asociados
- Uso del motor IA

### 3. Usuario Viewer
- Solo lectura
- Puede visualizar proyectos asignados
- No puede editar

---

# 5. 🔐 Autenticación y Seguridad

Registro mediante:

- Correo electrónico
- Contraseña segura

Requisitos:

- Validación de fortaleza de contraseña
- Feedback visual sobre seguridad
- Hash seguro de contraseñas
- JWT para autenticación
- Bloqueo temporal tras múltiples intentos fallidos
- Validación estricta de inputs
- Cumplimiento OWASP Top 10
- Security by Design
- Principio de Least Privilege

---

# 6. 📊 Restricciones del MVP

Debido al tiempo limitado y naturaleza open source:

- Máximo 3 proyectos por usuario
- Sin facturación
- Sin pagos
- Sin integraciones externas complejas
- Sin aplicación móvil en esta fase

---

# 7. 🏗 Arquitectura

## 7.1 Enfoque

Monolito Modular (Backend).

- Clean Architecture
- Domain Driven Design
- TDD obligatorio

## 7.2 Separación de Componentes

Aunque el backend será monolítico:

- Frontend (React) → Proyecto independiente
- Backend (FastAPI) → Proyecto independiente
- Mobile (futuro) → Proyecto independiente

## 7.3 Escalabilidad Futura

Posible migración a:

- Microservicios
- Event-Driven Architecture

Toda decisión será documentada mediante ADR.
